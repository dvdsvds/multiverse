# 이벤트(Event) 학습 Q&A 기록

내가 실제로 던진 질문/생각(원문 그대로) + 답변과 유도 과정.
주제: 매 tick마다 "무슨 이벤트가 일어날까"를 어떻게 뽑는가.

---

## Q1. 이벤트를 어떻게 고르나 (백지 출발)

### 🧠 내 상태 (원문)
> 그걸 생각하고 말하진 않았었어

### ✅ 출발점 — 제일 단순한 방법부터
- 이벤트 사전(교통사고·유학·승진·감기·로또...)에서 매 tick 하나 뽑아야 함.
- 제일 단순: **다 똑같은 확률로 무작위** (10개면 각 1/10).

---

## Q2. 다 같은 확률이면?

### 🧠 내 답 (원문)
> 같은 확률로 일어나면 부자연스럽지

### ✅ 정리
- 교통사고와 로또가 같은 확률 → 부자연스러움. "더 자주 / 덜 자주"가 있어야 함.
- 그러려면 각 이벤트가 뭔가를 하나 더 갖고 있어야 함 → **가중치.**

---

## Q3. 가중치 (내가 도출)

### 🧠 내 답 (원문)
> 가중치

### ✅ 정리 — 이벤트 사전에 가중치 추가
```
감기      → 가중치 30,  { 신경증 +0.05 }   (흔함)
승진      → 가중치 10,  { 외향성 +0.1 }
교통사고  → 가중치 5,   { 신경증 +0.3, vitality -(확률) }
로또당첨  → 가중치 1,   { ... }             (드묾)
```
- 가중치 클수록 자주 뽑힘. 감기(30)는 로또(1)보다 30배 자주.

---

## Q4. 가중치로 어떻게 뽑나 → 정규화

### 🧠 내 직감 (원문)
> 각 가중치 값을 46으로 나눠서 활용할 거 같아 이유는 모르겠지만

### ✅ 정리 — 이게 정규화(normalization)
총합 46(=30+10+5+1)으로 나누면:
```
감기:    30/46 = 0.652 (65.2%)
승진:    10/46 = 0.217 (21.7%)
교통사고: 5/46 = 0.109 (10.9%)
로또:     1/46 = 0.022 (2.2%)
                 합 = 1.0 (100%)
```
- 나누니 **합이 1** → 상대적 가중치가 진짜 **확률(%)**로 바뀜.
- 이게 정규화. 성격 벡터 때 나온 그 단어. 이유 모르고 정확히 해냄.

## Q5. 이벤트가 너무 많다? → 무한 아님, 2층 구조

### 🧠 내 지적 (원문)
> 지금 이벤트가 4개밖에 없어서 그렇지 이벤트는 엄청 많아
> 무한한 이벤트는 아니지 / 좋은·나쁜으로 나눠봤을 때 ... A와 B가 합쳐졌어

### ✅ 정리 — 종류와 세부를 분리
- **무한 아님**: 종류(교통사고·승진·불합격...)는 셀 수 있음(유한). 사전에 적을 수 있음.
- **A + B 합쳐진 2층 구조**:
```
바깥(A: 종류 여러 개, 사전에 나열)
├─ 불합격   → 심각도 확률 (B: 한 종류 안에서 정도가 다름)
├─ 교통사고 → 긁힘~즉사 확률
└─ ...
```
- 무한해 보이던 다양성 = **확률**이 담당(같은 사고라도 매번 다른 결과). 사전에 안 적어도 됨.
- → "사전에 다 못 적는다" 걱정은 **종류와 세부를 안 나눠서 생긴 착각**이었음.

## Q6. 한 사전에 다 넣기 vs 좋은/나쁜 2단계

### 🧠 내 판단 (원문)
> 먼저 정하고 세부 종류를 뽑는게 계산이 편하고 효율적일거 같은데?
> 가중치로 한 번에 뽑으면 가중치 문제 생길거 같아
> 계산이 꼬이고 이상한 부분에 가중치가 잘못 계산된다던가 비율 조절 꼬이고

### ✅ 정리 — 2단계가 맞음
- 한 사전에 다 넣으면: 좋은/나쁜 **비율 조절이 꼬임**, 가중치가 엉뚱한 데 잘못 먹는 실수 쉬움.
- **2단계 분리**:
```
1단계: 좋은 일 / 나쁜 일 (확률로)   ← 이 비율 = "우주 성향"(불행한 우주/평탄한 우주)
2단계: 정해진 쪽 사전에서 세부 종류 뽑기 (가중치)
3단계: 그 종류의 세부 결과는 확률로 (긁힘~즉사)
```
- 1단계 비율 = 우주 환경 파라미터(생존 난이도 등)와 연결. 한 숫자로 우주 성향 조절.
- 이것도 **"구조로 분리해 실수 원천 차단"** (Q1 우주 격리 때 원칙과 동일).

## Q7. 2단계에서 실제로 뽑는 법 → 누적합 + 이진 탐색

### 누적합(prefix sum)으로 구간 만들기
나쁜 사전 예:
```
불합격 20 → 누적 20   구간 [0, 20)
사고   5  → 누적 25   구간 [20, 25)
실직   8  → 누적 33   구간 [25, 33)
감기   30 → 누적 63   구간 [33, 63)
                     총합 63
```
- 각 이벤트가 가중치만큼 **구간 너비**를 차지. 감기(30)가 제일 넓음(제일 흔함).
- 0~63 난수 r 뽑기 → r=28이면 [25,33) = **실직 당첨**.
- 난수 범위를 0~1 대신 **0~총합**으로 잡으면 정규화(나눗셈) 없이도 동작.

### 🧠 "무슨 알고리즘이지?" (원문)
> 누적합이면 앞에서부터 계속 쌓아가는 형식인데 이게 무슨 알고리즘이지?

두 작업이 섞여 있었음:
- **작업 1 — 누적합 쌓기**: `누적 += 가중치`. 그냥 **prefix sum**. 특별한 알고리즘 아님.
- **작업 2 — r이 들어갈 위치 찾기**: 누적합은 **정렬된 배열** → 값 찾기 = 탐색 알고리즘.

### 🧠 탐색 방법 (원문)
> O(logn)?

- **이진 탐색(binary search).** 정렬된 누적합에서 "r보다 큰 첫 구간"을 절반씩 잘라 찾음.
- 선형 $O(n)$보다 빠름. 종류가 수백 개면 확실히 이득 ("두 방법 있으면 효율적인 쪽" 원칙).
- **조건**: 누적합이 매 tick 안 바뀌어야 함. 이벤트 사전은 고정이라 **누적합을 한 번만 미리 만들어** 재활용 → 이진 탐색 이득 온전.

### 최종 뽑기 구조
```
[사전 준비 - 한 번]
  누적합 배열: [20, 25, 33, 63]   (prefix sum, O(n))

[매 tick]
  r = random(0, 63)
  이진 탐색으로 r의 구간 찾기       (O(log n))
  → 그 구간 이벤트 당첨
```

## 🔑 이벤트 뽑기 전체 뼈대 (내가 유도한 흐름)
```
무한 아님(종류 유한)
  → 좋은/나쁜 2단계 분리 (1단계 비율 = 우주 성향)
  → 세부 종류는 가중치로
  → 정규화(합=1)로 확률화 (또는 0~총합 난수로 나눗셈 생략)
  → 누적합(prefix sum)으로 구간 만들기
  → 이진 탐색(O(log n))으로 뽑기 (누적합은 한 번만 준비)
  → 뽑힌 이벤트의 세부 결과는 확률로 (vitality 확률 감소와 연결)
```
