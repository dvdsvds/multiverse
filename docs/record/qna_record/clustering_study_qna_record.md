# 클러스터링 & 차원 축소 학습 Q&A 기록

내가 실제로 던진 질문/생각(원문 그대로) + 답변과 유도 과정.
주제: 성격 벡터 N개가 몇 유형으로 갈라지나(분기 스펙트럼), 그리고 고차원을 어떻게 다루나.

---

## 0. 클러스터링이란

- base 기준 거리(유클리드)는 "각자가 base에서 얼마나 멀어졌나"였음.
- 클러스터링은 질문이 다름: "이 N개가 **자기들끼리** 몇 덩어리로 뭉치나" = 성격 유형 = 분기 스펙트럼.

### 🧠 내 정리 (원문)
> 거리가 가까운 점들은 비슷한 유형인거지?

### ✅ 정답 — 그게 클러스터링의 정의
- **가까운 점 = 비슷한 유형 = 같은 덩어리.**
- 유클리드 거리를 base 기준이 아니라 **점들끼리 서로** 재는 데 씀. 도구는 그대로, 대상만 바뀜.

---

## Q1. 컴퓨터한테 뭘 알려줘야 덩어리를 나누나?

점들이 애매하게 퍼져 있으면 1덩어리인지 2덩어리인지 사람마다 다르게 봄. "얼마나 가까워야 같은 덩어리"인지 경계가 필요.

### 🧠 내 생각 (원문)
> 떨어져있는 거리를 계산해야 될 거 같은데? 다른 걸 알려줘야하나?

### ✅ 정리 — 접근을 뒤집음
- "얼마나 가까우면 묶나"(경계값)를 정하는 대신, **"몇 덩어리로 나눌지"(개수 k)**를 정해주는 방법이 있음 = **k-means**.
```
k-means (k=3 예):
 1. 중심점 3개를 아무 데나 찍음
 2. 각 점을 제일 가까운 중심점에 배정 (유클리드 거리)
 3. 배정된 점들의 진짜 가운데로 중심점 이동
 4. 2~3을 중심점이 안 움직일 때까지 반복
```
- 답: "몇 개(k)"를 알려줘야 함. 거리 계산은 컴퓨터가, 나는 개수만.

### 모순 발견
- 나는 **몇 유형인지 몰라서** 클러스터링을 하는데, k-means는 "몇 개인지 먼저 말해줘"라고 함 → 앞뒤가 안 맞음. (다음 Q에서 해결)

## Q2. k를 모르는 문제 — 조사한 방법들 분류

### 🧠 내가 조사 (원문)
> 엘보우 방법, 실루엣 점수, 계층적 군집화, DBSCAN, DPGMM ... 계층적 군집화가 맞는 것 같고 엘보우는 안 맞는 것 같아

### ✅ 정리 — 5개가 사실 두 부류 (섞여 있었음)
- **A. k를 몇으로 할지 도와주는 것** (k-means는 그대로 쓰되 k 선택을 도움): **엘보우 방법, 실루엣 점수**
- **B. k를 아예 안 정해도 되는 알고리즘**: **계층적 군집화, DBSCAN, DPGMM**
- → 엘보우는 B(알고리즘)가 아니라 A(k 고르는 도구). 계층적과 **경쟁 관계가 아님.** 층위가 다름.

### 계층적 군집화 (내가 처음 고른 것)
```
1. 점 N개가 각자 1덩어리
2. 제일 가까운 두 덩어리를 합침
3. 반복 → 결국 1덩어리. 전 과정을 나무그림(덴드로그램)으로 남김
```
- 장점: **k를 미리 안 정해도 됨.** 나중에 "여기서 자르면 3덩어리" 하고 정함.

## Q3. 계층적의 약점 → 규모 문제

### 🧠 내 판단 (원문)
> 감당이 안되네 흠 그러면 이 문제를 어떻게 풀면 좋지 힌트가 있나?

### ✅ 정리
- 계층적은 **모든 점 쌍의 거리**를 계산 → 점 N개면 거리 계산 ≈ **N²개.**
```
N=1,000  → 약 100만 번
N=100만  → 약 1조 번  ← 감당 불가
```
- 이 프로젝트는 N이 커질 수 있음(1,000 → 수백만) → 계층적은 대규모에서 무너짐.

### 해결 경로 두 갈래 + 내 연결
- **길 A: 알고리즘 교체** — N²이 아니라 N에 거의 비례하는 걸로. → **k-means**(대규모 OK).
- **길 B: 데이터 축소** — 일부만 뽑아 클러스터링. (몬테카를로에서 쓴 방식)
- 내 답(원문): "b가 몬테카를로랑 더 가까운 것 같은데" → 맞음. 단 B가 정당한 이유 = **통계적 수렴**(충분히 뽑으면 표본이 전체 유형 분포를 대표).

### ✅ 최종 — 굳이 A/B 안 골라도 되는 답
- **k-means**는 N에 거의 비례(빠름) → 100만도 OK.
- k를 모르는 문제는 **엘보우/실루엣**이 해결(내가 밀어냈던 그것이 바로 이 상황용 도구).

---

## Q4. 최종 선택 — k-means + 엘보우/실루엣

### 🧠 내 결론 (원문)
> k-means + 엘보우/실루엣이 완전 적합하네

### ✅ 정리 — N이 크다는 조건이 선택을 뒤집음
```
계층적:            k 안 정해도 됨(장점) / N²이라 대규모 느림(단점)
k-means+엘보우/실루엣: 빠름·대규모 OK(장점) / k 여러 개 시도해 고름(도구가 도움)
```
- 조사 땐 계층적이 좋아 보였으나, **"규모(N 큼)" 기준을 넣으니 답이 뒤집힘.** (실제 조건에 대보고 정하는 원칙)
- 두 도구가 서로 약점 보완: k-means 약점(k 필요)을 엘보우/실루엣이 채움.
- **엘보우**: k를 2,3,4,5...로 늘리며 "덩어리 안 흩어짐"이 확 줄다 완만해지는 꺾이는 지점(팔꿈치)을 k로.
- **실루엣**: 각 k의 "덩어리가 얼마나 깔끔히 나뉘나"를 점수화, 제일 높은 k. 보통 둘을 같이 봄.

## Q5. 차원 축소 — 왜 필요한가

두 이유:
- **시각화**: 성격이 5차원(나중 12차원). 화면은 2D. 사람은 3차원까지만 봄 → 눌러야 그림.
- **차원의 저주**: 차원 많으면 점들이 다 비슷하게 멀어 보여 클러스터가 안 뭉침(persona vector 때 나온 것).

### 🧠 "그냥 3개 버리면?" (원문)
> 서로 영향이 있는 3개인데 그걸 버려버리면 데이터의 복잡도가 줄어들지 않을까?

### ✅ 정리 — 복잡도는 줄지만 "나쁜 감소"
- **좋은 감소**: 겹치는 정보를 합쳐 줄임. 정보 보존.
- **나쁜 감소**: 정보를 그냥 버려 줄임. 차원도 정보도 사라짐. ← "3개 버리기"가 이것.
```
신경증 버리면 → "이 사람 신경증 높았나?"를 영영 모름. 교통사고로 치솟은 사람과 평온한 사람이 똑같아 보임.
```
- 내가 persona vector 때 한 말 "서로 영향받는 것끼리 묶자" = **좋은 감소(합치기)** = 차원 축소.
```
나쁜(버리기): [O,C,E,A,N] → [O,C]           (3개 삭제)
좋은(합치기): [O,C,E,A,N] → [새축1, 새축2]   (5개 정보를 2개에 압축)
```
- 새 축 = 원래 축들을 **섞어서 만든** 축. 대표 도구 = **PCA.**

## Q6. PCA는 뭘 기준으로 새 축을 만드나

### 🧠 내 직감 (원문, 뒤집어야 함)
> 다닥다닥 뭉쳐 있는 방향이지 않을까

### ✅ 정리 — 반대. 넓게 퍼진 방향이 정보 많음
- **뭉친 방향**: 다들 값이 비슷 → 사람을 **구분 못 함** → 있으나 마나(버려도 손해 적음).
- **퍼진 방향**: 왼쪽~오른쪽 다양 → 사람을 **구분해줌** → 정보 많음.
- "구분해주는 축 = 정보 많은 축"이고, 구분은 **퍼졌을 때** 생김.
- 퍼진 정도 = **분산(variance).** PCA는 **분산 큰 방향부터** 새 축으로 잡음.
```
PCA:
 1. 제일 넓게 퍼진(분산 큰) 방향 → 새축1
 2. 그다음 퍼진 방향 → 새축2
 3. 새축1, 새축2만 남김 → 5D → 2D (정보 최대 보존)
 4. 2D라 화면에 그릴 수 있음 + 클러스터링도 잘 됨
```
- "그냥 버리기"가 나빴던 이유 완결: 그냥 버리면 정보 많은(퍼진) 축을 버릴 수도. PCA는 **제일 안 퍼진 방향부터** 버려 손해 최소.

---

## 🔑 클러스터링 & 차원 축소 최종
```
[차원 축소]
  PCA로 5D(→12D) 성격 벡터를 2D/3D로 압축 (분산 큰 방향부터 보존)
     → 시각화 가능 + 차원의 저주 완화

[클러스터링]
  k-means로 점들을 k덩어리로 (빠름, 대규모 OK)
  k는 엘보우/실루엣으로 선택 (몇 유형인지 몰라도 됨)
     → 성격이 몇 유형으로 갈라졌나 = 분기 스펙트럼

[대규모 시]
  필요하면 표본만 뽑아 클러스터링(통계적 수렴이 표본 대표성 보장)
```
- 도구 선택 근거: **N이 커질 수 있다** → N² 계층적 대신 N인 k-means.
- 차원 축소는 버리기(정보 손실)가 아니라 합치기(정보 보존)여야 함 = PCA(분산 기준).
