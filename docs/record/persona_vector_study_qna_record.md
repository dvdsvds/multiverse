## Q1. 벡터가 뭔지 모르겠다 (아는 건 std::vector뿐)

### 🧠 내 출발점 (원문)
> 아예 벡터라는거 개념이 없어 vector밖에 몰라 연속적인 메모리 공간

### ✅ 정리
- `std::vector<double>`에 `[0.5, 0.2, 0.8]` = 연속 메모리에 double 3개. 내가 아는 그대로.
- 수학·데이터의 **벡터도 정확히 이것.** 딱 하나 추가됨: 각 칸이 **"무언가를 나타내는 숫자"**라는 의미를 가짐.

| 인덱스 | 0 | 1 | 2 |
|---|---|---|---|
| 값 | 0.5 | 0.2 | 0.8 |
| 의미 | 외향성 | 신경증 | 위험선호 |

- **벡터 = 여러 숫자를 순서대로 묶고, 각 자리가 특정 의미를 갖게 한 것.**
- 성격 벡터 = 한 사람의 성격을 숫자 몇 개로 표현한 것.

## Q2. 왜 글자가 아니라 숫자로?

### 🧠 내 답 (원문)
> base가 있으니까 글자로 하면 너무 애매모호해져

### ✅ 정리
- divergence = base에서 **얼마나** 벌어졌나. "얼마나"를 재려면 숫자여야 함.
- 글자면: base "외향적" vs 현재 "소심함" → 얼마나 벌어졌는지 계산 불가.
- 숫자면: 외향성 0.8 → 0.3 = **0.5만큼 벌어짐.** 정확히 측정 + 우주끼리 비교 가능.
- 성격이 숫자여야 → 거리 측정 → divergence → 클러스터링이 전부 가능해짐.

## Q3. 차원 용어 혼동 — 성격 벡터가 중첩 배열인가?

### 🧠 내 혼동 (원문)
> 성격 벡터가 차원 벡터는 아니라는거지?
> [ [], [] ] 이런 느낌인거 있잖아

### ✅ 정리 — "차원"이라는 단어가 두 군데서 다르게 쓰임
- **자료구조의 차원** = 배열이 몇 겹 중첩됐나.
  - `[1,2,3]` = 1차원 배열 / `[[1,2],[3,4]]` = 2차원 배열
- **벡터(수학)의 차원** = 숫자가 몇 개 들었나 (= `.size()`).
  - `[0.5, 0.2, 0.8]` = 3차원 벡터

성격 벡터는 **1차원 배열**(중첩 아님)이고, 수학 눈으로는 **3차원 벡터**. 같은 걸 두 분야가 다르게 세는 것뿐.

| 같은 것 `[0.5, 0.2, 0.8]` | 어떻게 셈 |
|---|---|
| 자료구조 눈 | 1차원 배열, 원소 3개 |
| 수학 눈 | 3차원 벡터 |

→ 성격 벡터는 `[[], []]`가 아니라 `[숫자, 숫자, 숫자]` 한 줄.

## Q4. 성격 벡터의 칸을 뭘로, 몇 개로?

### 🧠 내가 조사해온 것 (원문 요약)
- 심리학 모델: Big 5(OCEAN), TCI 기질·성격 요인
- 그 외: 유전/생물학적 요인, 환경/경험적 요인, 삶의 주요 사건 등

### ✅ 정리 — 두 종류로 분리
- **A. 성격을 "구성"하는 항목** (= 벡터의 칸 후보): Big 5, TCI 요인들
- **B. 성격에 "영향"을 주는 요인** (= 칸 아님): 유전, 애착, 삶의 사건 등
  - → B는 전부 우리가 이미 만든 **이벤트 + base + 환경 파라미터.** 벡터의 칸이 아니라 벡터를 **바꾸는 원인.**

```
base (유전·타고난 기질)  →  초기 성격 벡터
이벤트 (삶의 사건)        →  f를 통해 성격 벡터 변화
성격 벡터 (Big5/TCI)     →  지금 상태 = A
```

내가 "삶의 주요 사건 = 이벤트"라고 스스로 연결함 → B가 전부 이벤트/base/환경이라는 게 드러남.

## Q5. 칸을 많이 만들면 뭐가 힘들어지나? (내가 유도한 지식)

### 🧠 내가 떠올린 것 (원문)
> 차원 curse, 계산 복잡도 및 메모리 급증, Overfitting 위험 증가, 노이즈 영향력 확대

### ✅ 개념 정리 — 이 프로젝트에 대입

**차원의 저주 (Curse of Dimensionality)**
- 차원(칸)이 많아질수록 데이터가 넓은 공간에 흩뿌려져, 점들 사이 거리가 다 비슷하게 멀어 보임.
- → 나중에 클러스터링할 때 **클러스터가 안 뭉침.** 내가 보려는 "분기 스펙트럼"이 흐려짐. ← 가장 크리티컬.

**계산 복잡도 / 메모리 급증**
- 우주 1,000개 × tick 1,000 × 차원 수. 차원이 5냐 15냐가 그대로 곱해짐.

**노이즈 영향력 확대**
- 의미 없는 미세 변동(노이즈)이 차원마다 쌓여서 전체 결과를 흔듦.

**Overfitting**
- 원래는 "학습 모델이 훈련 데이터에 과하게 맞춰지는" 문제. 우리처럼 규칙($f$)로 굴리는 시뮬레이션엔 직접 해당은 덜 됨.
- 다만 "차원이 많으면 의미 없는 변동에 휘둘린다"는 감각은 노이즈 확대와 통함.

**→ 판단 기준**: tick 때 쓴 "목적에 안 보태면 버린다"를 여기도 적용. 차원은 표현력과 저주 사이 균형.
- 너무 적으면(2~3): 성격이 단순해져 다양한 갈라짐이 안 나옴 (표현력 부족).
- 너무 많으면(15+): 차원의 저주로 클러스터 흐려짐 + 계산 무거움.

## Q6. 서로 영향받는 것끼리 묶으면 안 되나? (내가 유도한 지식 = 차원 축소)

### 🧠 내 발상 (원문)
> 둘이 합쳐서 서로 영향 받는 애들끼리 묶으면 안되나?

### ✅ 개념 정리 — 이게 바로 **차원 축소(Dimensionality Reduction)**
- 이름만 몰랐을 뿐, 정식 기법을 정확히 떠올림.
- **원리**: 서로 같이 움직이는(상관관계 높은) 칸들을 하나로 묶어, 정보 손실을 최소화하며 개수를 줄임.
- 예:
  - Big 5 "신경증" ↔ TCI "위험회피" → 비슷한 걸 다르게 잰 것. 같이 움직임.
  - Big 5 "외향성" ↔ TCI "자극추구" → 상당히 겹침.
- 대표 도구: **PCA (주성분 분석)** — 상관 높은 축들을 합쳐 핵심 축 몇 개로 압축.

### ⚠️ 단계 분리 (내가 "정리가 안 된다"고 느낀 이유)
동시에 두 개를 고민해서 머리가 안 정리됐던 것:
1. **지금 정할 것**: 성격 벡터의 칸을 뭘로 할지 (단순하게).
2. **나중 분석 단계**: 결과가 고차원이라 클러스터가 흐리면 그때 PCA로 묶어 줄임.
- → "묶기"는 분석 단계에서 **도구가 알아서** 하는 일. 지금 손으로 정할 게 아님. 지금은 단순하게.

## Q7. 결론 — 성격 벡터 확정

### 🧠 내 결정 (원문)
> 처음에는 bf(Big 5)로 먼저하고 결과가 좀 괜찮게 나온다하면 tci도 붙혀서 pca적용시키자

### ✅ 최종 정리
1. **1차: Big 5(5차원)만.** 단순하게 시작, 차원의 저주 걱정 없이 구조부터 검증.
2. **2차: 결과 괜찮으면 TCI 추가 → PCA로 축소.** 세밀도 올리되 늘어난 차원은 차원 축소로 정리.
- Big 5는 서로 독립적이게 설계된 모델 → 이미 안 겹쳐서 묶을 필요가 적음.
- "결과가 괜찮으면"이라는 판단 = 미리 다 정하지 않고 **실측으로 결정** (기획서 10번의 태도와 동일).

**확정된 성격 벡터:**
```
persona = [개방성, 성실성, 외향성, 우호성, 신경증]   ← 5차원 (Big 5 / OCEAN)
```

---

## 부록. Big 5 (OCEAN) 다섯 축의 의미

| 축 | 높으면 | 낮으면 |
|---|---|---|
| **개방성** (Openness) | 호기심·상상력, 변화 즐김 | 익숙한 것 선호, 실용·전통적 |
| **성실성** (Conscientiousness) | 계획적, 책임감, 목표지향 | 즉흥적, 느슨, 산만 |
| **외향성** (Extraversion) | 사교적, 활동적, 말 많음 | 조용함, 혼자 편함(내향) |
| **우호성** (Agreeableness) | 친절, 공감, 잘 맞춰줌 | 경쟁적, 비판적, 자기주장 |
| **신경증** (Neuroticism) | 걱정·스트레스에 예민, 기복 큼 | 정서 안정, 침착, 둔감 |

- **신경증(Neuroticism)** = 부정적 감정(불안·스트레스·우울)을 얼마나 잘 느끼는지. 병명 아님, "노이로제"와 다름.
- 그래서 `교통사고 → { 신경증: +0.3 }`이 성립: 큰 사고 → 불안·스트레스에 예민해짐.

```
persona = [개방성, 성실성, 외향성, 우호성, 신경증]
           호기심   계획성   사교성   협조성   불안성
```
