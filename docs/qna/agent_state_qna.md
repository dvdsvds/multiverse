# Agent / State 학습 Q&A 기록

내가 실제로 던진 질문(원문 그대로) + 그 아래 답변과 기본 지식.
"내가 어떻게 생각했고, 어디를 어떻게 고쳤는지"를 남기기 위한 기록.

주제: 문서 3번 "Agent State Engine" — Agent(개체)와 State(상태)를 코드로 어떻게 설계할지.

---

## Q1. 생성자의 변수 값들은 모두 같아야 하나?

### 🧠 내가 생각한 것 (원문)
```
1. Agent를 class로 선언하고, State를 class의 변수로 선언해야 한다고 생각하는데,
   여기서 생성자의 변수 값들은 모두 같아야하나?
```

### ✅ 답변 + 기본 지식

**결론: 아니다. 일부는 같고, 일부는 달라야 한다.**

앞에서 잡은 개념과 연결 → 모든 Agent가 같은 `base`에서 **시작**하지만 각자 다르게 **흩어진다.** 그 "같음"과 "다름"이 State 안에 둘 다 들어있음.

State 변수를 세 종류로 나눠서 봐야 함:

**① 같아야 하는 것 (base, 불변)**
- `dna_base` — 모든 우주의 '나'가 공유하는 출발점.
- 생성자에서 모든 Agent에게 **똑같이** 넣어줌. 이게 갈라짐을 재는 기준(자).

**② 처음엔 같지만 곧 달라지는 것 (동적)**
- `persona`, `intelligence`, `xp`, `vitality`...
- 시작값은 base에서 복사해 같게 두지만, tick이 지나며 각자 환경 때문에 **바뀜.**
- → 초기값은 공통이어도 변수 자체는 우주마다 독립.

**③ 처음부터 다른 것 (우주에서 옴)**
- `status`(태어났는지), environment 값들(`seed`, 생존 난이도 등)은 우주마다 다름.

**→ 생성자 설계 방향**: 같은 값을 하드코딩하는 게 아니라,
- "공통 base" → 인자로 받아서 모두 같게
- "우주별 환경/seed" → 인자로 받아서 각자 다르게 (주입)

### 💡 추가로 짚은 것 — Agent와 State를 분리할지 합칠지
- **합치기**: `Agent` 클래스 하나에 상태 변수 다 넣기 (단순).
- **분리하기**: `Agent`(행동/로직) + `State`(데이터) 나누기.
- **효율 관점에서는 분리가 유리.** 나중에 우주 1,000개를 NumPy 배열로 한 번에 굴리려면 State가 순수 데이터로 떨어져 있는 게 훨씬 편함.
- 단, 이건 지금 결정 안 해도 됨.

## Q2. base의 기준은? 지금 생각 안 해도 되나?

### 🧠 내가 생각한 것 (원문)
```
2. 여기서 Agent가 base객체를 만든다고 생각하는데 base의 기준은 어떻게 되나?
   지금 여기서 생각을 하지 않아도 되나?
```

### ✅ 답변 + 기본 지식

**결론: 지금은 생각 안 해도 된다. 미뤄도 되는 게 맞다.**

**이유 ①: base의 구체적 값은 결과 그림에 거의 영향이 없다.**
- base는 그냥 "출발선"이라 어디에 긋든 상관없음.
- 중요한 건 출발선 위치가 아니라 **거기서 얼마나 벌어지느냐.**
- 육상 비유: 출발선을 트랙 어디에 긋든 "누가 얼마나 앞섰나"는 똑같이 잴 수 있음.

**이유 ②: 지금 정할 수도 없다.**
- base의 형태(성격 차원 K가 몇 개인지, 각 차원이 뭘 의미하는지)는 **성격 업데이트 규칙 $f$를 정해야 결정됨.**
- $f$가 "외향성이 이렇게 바뀐다"라고 정의돼야 → "외향성이 성격 벡터에 있어야겠네"가 나옴.
- **순서: $f$ → 성격 차원 → base 초기값.**

**→ 지금 base에 대해 필요한 것은 딱 하나:**
"모든 Agent가 공유하는 고정된 벡터가 존재한다"는 것만 코드 구조에 반영.
구체적 숫자는 나중에. 지금은 `dna_base`라는 **자리(placeholder)**만 만들어두면 됨.

## 정리

| 질문 | 결론 |
|---|---|
| 생성자 변수 다 같아야 하나? | ❌ 아니다. base는 공유(같게), seed/환경은 주입(다르게) |
| base 구체값 지금 정해야 하나? | ❌ 아니다. "공유 고정 벡터가 있다"는 구조만 잡아두면 충분 |

**다음에 정할 것**: 계속 미뤄둔 **성격 업데이트 규칙 $f$.**
이게 정해져야 성격 차원도, base 값도, State에 뭐가 들어갈지도 다 따라 정해짐.

## State 변수 3분류 (복습용)
```
① 같아야 함 (base, 불변)      → dna_base
② 처음 같다가 달라짐 (동적)   → persona, intelligence, xp, vitality
③ 처음부터 다름 (우주에서 옴) → status, seed, 생존난이도 등
```
생성자: ①은 공유, ③은 주입, ②는 ①에서 복사해 초기화.
